# Decisions log

Índice de decisiones **arquitectónicas/técnicas** del repo. Una fila por decisión (con o sin ADR). El ADR es obligatorio si la decisión es one-way door o afecta ≥2 packages.

Las decisiones de **producto/negocio** (alcance, tandas, releases, impactos visuales asumidos, reglas de proceso del PO) no van acá: se registran como `D-XXX` en [docs/product/decisiones.md](../product/decisiones.md). Test de frontera: ¿la podría tomar un arquitecto sin el PO? → va acá. ¿La tiene que tomar el PO aunque no supiera programar? → es una `D-XXX`. Si tiene las dos caras, lleva una entrada en cada registro, cada una contando su cara y linkeando a la otra (patrón D-029 ↔ ADR-022).

## Cómo agregar una entrada

1. Verificar la frontera: si la decisión es de producto/negocio, va como `D-XXX` a [docs/product/decisiones.md](../product/decisiones.md), no acá.
2. Si la decisión afecta ≥2 packages o es one-way door → crear ADR en [adr/](adr/) siguiendo formato MADR.
3. Agregar fila acá con: fecha ISO, dominio (`frontend`/`tokens`/`components`/`build`/`ci`/`transversal`), resumen ≤3 líneas, link al ADR si aplica.
4. Si la decisión reemplaza una previa: agregar nueva fila + actualizar la fila del ADR reemplazado en su archivo.
